# 사용자별 사용 시나리오

화면 이름과 버튼 이름은 실제 화면 그대로다. 등장인물은 모두 가상이다.

> 가상교수01(관리자2), 가상조교01(관리자1), 가상학생01~30(참여자)
> 대회 "2026-2 머신러닝", 과제 "유방암 진단", 1차 마감 11/20 17:00(3회), 2차 마감 11/27 17:00(5회)

예시 대회로 바로 해 보려면 `./dev.sh start` → `./dev.sh demo`를 실행한다. 계정은 `demo_prof`(관리자2), `demo_ta`(관리자1), `demo_stu01~11`(참여자)이고, 비밀번호는 아이디와 같다(로컬 시연 전용).

## 1. 관리자2 (교수): 대회를 만들고 최종 결정한다

| 단계 | 화면 → 버튼 | 결과 |
|---|---|---|
| 0. 계정 받기 | 웹에서는 만들 수 없다. 서버 담당자가 `./dev.sh admin2` 실행 | 관리자2 계정 생성(감사 로그) |
| 1. 대회 개설 | 내 대회 → **대회 개설** → 대회명 | 참여 코드 자동 생성(예: `K7QM-3XPA`) → 학생·조교에게 공유 |
| 2. 과제 추가 | 대회 화면 → **+ 과제 추가** → 과제명, 지표, 점수 방향(비우면 자동), id·정답 컬럼 이름 | 과제 생성 |
| 3. 파일 등록 | 과제 개요 → 파일 등록 → 정답(비공개), 공개 테스트 feature, 공개 학습 데이터(선택) | 정답에서 행 수·허용 값 자동 계산. feature에 정답 컬럼이 있으면 거부 |
| 4. 마감일 | 과제 개요 → 마감일 추가 → 시각 + 제출 횟수(여러 개 가능) | 구간마다 횟수를 따로 센다 |
| 5. 조교 지정 | 대회 화면 → **회원 관리** → 조교 줄의 **관리자1로 지정** | 조교도 먼저 참여 코드로 가입해 있어야 한다. 제출 기록이 있으면 지정 불가 |
| 6. 운영 중 | 과제 탭 **리더보드**(실명 보임), **제출 목록**, **검토** | 조교의 제안을 보고 **결정**한다. 받아들이지 않으면 **반려**, 확정을 풀려면 **재검토**. 부적합 결정 칸에는 조교의 사유가 미리 채워지고, 그 문장이 학생 본인에게 보인다 |
| 6-1. 일괄 확정 | 검토 → **승인 대기** 표에서 체크(또는 맨 위 '모두 선택') → **선택한 제출 적합 확정** | 표에 '문제 된 검사'와 조교 사유가 함께 보인다. 체크할 수 있는 것은 '적합 제안'이면서 리포트가 '문제 없음'이거나 '주의'의 이유가 V4 셸 명령·셀 실행 순서뿐인 것(V3 오답 일치·V7 방법 점검은 참고·안내라 판정에 들어가지 않는다). V1·V5 주의(손수정 가능성), 의심, 판정 불가는 한 건씩 |
| 7. 회원 문제 | **회원 관리**(3절) | 잠금 풀기, 임시 비밀번호, **참가 정지** |
| 8. 마감 후 | 과제 탭 **최종 성적** → 확정 현황 → **성적표 CSV** | 전원 확정이면 "최종 확정" 표시 |

**주의**
- 참여 코드가 유출되면 대회 화면에서 **재발급**한다. 이미 가입한 사람은 영향이 없다.
- 정답 파일과 점수 방향은 채점된 제출이 생긴 뒤에는 바꿀 수 없다(순위가 뒤집히는 것 방지).

## 2. 관리자1 (조교): 검증 리포트를 보고 제안한다

| 단계 | 화면 → 버튼 | 결과 |
|---|---|---|
| 1. 가입 | 회원가입 → 참여 코드 입력 | 처음에는 참여자 |
| 2. 지정받기 | (교수가 회원 관리에서 지정) | 과제에 **검토·제출 목록·최종 성적** 탭이 생긴다. 제출 버튼은 사라진다 |
| 3. 검토 | 과제 → **검토** → 점수 높은 기록부터(R10) → 한 건 열기 | 검증 리포트 V1(노트북 재실행 일치율)~V7(V3·V7은 참고·안내), 노트북 보기, 제출 파일 받기. 검증이 아직 진행 중이면 위에 현재 단계가 보이고, 끝나면 화면 위에 **알림 띠 + [새로고침]** |
| 3-1. 다시 검증 | 리포트 → **검증 다시 실행** | **진행 화면**으로 이동: 대기열(앞에 N건) → 파일·코드(V2·V3·V4) → 모델(V5) → 노트북(V1, 제한 시간 대비 경과) → 저장. 3초마다 저절로 갱신, 끝나면 [리포트 보기] |
| 4. 제안 | **적합 제안 / 부적합 제안** + 사유 | 리더보드는 그대로이고, 교수 결정을 기다린다(R11) |
| 5. 학생 문의 | **회원 관리** → **잠금 풀기** / **임시 비밀번호** | 3절 참고. 참가 정지는 할 수 없다 |
| 6. 다시 보기 | 과제 → **제출 목록** → 그 줄의 **CSV / 노트북 / 노트북 보기 / 모델 / 상세** | 검토가 끝나 검토 목록에서 빠진 제출도 파일·검증 리포트·검토 이력을 다시 연다(교수도 같음) |

예시: 가상학생03의 V1 일치율이 96.5%로 "주의"다. 노트북을 열어 보니 결과 CSV 6줄을 손으로 고친 흔적이 있다. **부적합 제안**(사유: "노트북 출력과 제출 CSV 6행 불일치")을 하고, 교수가 결정하면 학생03의 다음 기록이 검토 목록에 올라온다(R12).

## 3. 회원 관리 (관리자1·관리자2만)

대회 화면 → **회원 관리**. 실명, 아이디, 역할, 별칭, 제출 수, 마지막 로그인, 상태가 보인다. 실명·아이디·별칭으로 검색할 수 있다.

| 상황 (가상) | 누가 | 버튼 | 결과 |
|---|---|---|---|
| 학생01이 비밀번호를 5번 틀려 "10분 후 다시"가 뜸 | 조교·교수 | **잠금 풀기** | 바로 다시 로그인 가능 |
| 학생02가 비밀번호를 잊음 | 조교·교수 | **임시 비밀번호** | 화면에 한 번만 `Kp7d-xQ3m-RtwZ` 형태로 보인다 → 본인에게 직접 전달 → 학생02는 로그인하자마자 새 비밀번호로 바꿔야 다른 화면을 쓸 수 있다. 학생02가 다른 곳에 로그인해 두었던 세션은 끊긴다 |
| 학생05가 대리 시험 의심 | 교수만 | **참가 정지** | 그 대회에 들어오거나 제출할 수 없다. 기록·점수는 남는다. 성적에서 빼려면 검토에서 **부적합** 결정 |
| 오해가 풀림 | 교수만 | **정지 해제** | 다시 참여 |

**막혀 있는 것 (보안)**
- 조교는 **어느 대회에서든 관리자인 사람**의 비밀번호를 초기화할 수 없다. 예를 들어 가상조교01이 다른 대회 조교인 가상조교02의 비밀번호를 바꾸면, 그 계정으로 그 대회 정답을 볼 수 있게 되기 때문이다. 버튼도 보이지 않고, 주소로 직접 요청해도 403이다.
- 임시 비밀번호 화면은 브라우저에 저장되지 않는다(`no-store`). 임시 비밀번호 값은 감사 로그에도 남기지 않는다.
- 모든 동작(잠금 해제, 임시 비밀번호, 정지·해제)은 감사 로그에 "누가, 누구에게"로 남는다.
- 계정 삭제는 없다. 제출·감사 기록을 보존하고, 정지로 대신한다.

## 4. 참여자 (학생): 제출하고 결과를 본다

| 단계 | 화면 → 버튼 | 결과 |
|---|---|---|
| 1. 가입 | 회원가입 → 아이디, 실명, 비밀번호(10자 이상), **참여 코드** | 코드 없이는 가입 불가(R13). 익명 별칭 자동 부여(예: "참여자 7QMX") |
| 2. 자료 받기 | 내 대회 → 과제 → 개요의 자료: 학습 데이터, 테스트 feature, **제출 견본 CSV** | 견본으로 형식(`id,label`, 행 수) 확인 |
| 3. 모델 만들기 | (내 PC) 노트북에서 `train.csv`·`test.csv`를 읽어 `submission.csv` 저장. `random_state` 고정 권장 | 샌드박스가 이 노트북을 그대로 다시 실행해 비교한다 |
| 4. 제출 | 과제 개요 → **제출 시작**(코멘트 선택) → 예측 CSV, 노트북, 모델 파일 → **올리고 제출 완료** | 누른 시각이 마감 판정 기준(R1). 형식이 틀리면 "형식 오류", **횟수 차감 없음**(R3) |
| 5. 결과 | 과제 개요 → 내 제출 | "채점 대기" → 몇 초 뒤 화면 위에 **"제출 #12 채점 완료 (0.9649) [새로고침]"** 알림 → 새로고침하면 점수, "사용 1 / 남은 2". 리더보드를 열어 두면 순위가 바뀔 때 "순위가 바뀌었습니다" 알림 |
| 6. 순위 | 과제 → **리더보드** | 본인 최고점 기준, 이름 대신 별칭(R8) |
| 그 밖 | 상단 **대회 추가**(다른 대회 코드), **비밀번호 변경** | 한 계정으로 여러 대회 참여 |

예시: 가상학생01이 16:59:59에 **제출 시작**을 누르고 17:02에 업로드가 끝나면 1차 구간으로 채점된다. 17:00:00에 누르면 2차 구간이다.

## 5. 한 대회의 흐름 (시간 순)

```
교수   대회 개설 → 과제·정답·마감 등록 → 코드 공유
학생   가입(코드) → 자료 받기 → 노트북 작성 → 제출 ─┐
조교   가입(코드) → (교수가 관리자1 지정)              │
시스템                                worker: 채점 → 리더보드 → 샌드박스 검증(V1~V6)
조교                                  검토: 리포트 보고 적합/부적합 제안
교수                                  결정 → (부적합이면 다음 기록이 검토로) → 최종 성적 CSV
```
